## Confirmed P1 Bugs
1. **Move Journal Destructive Ghost Reconciliation**: `MoveReconcilerService` blindly deletes the source ghost during journal replay without checking `updatedAt`. If a runtime move partially fails, the UI throws and reverts, leading the user to edit the source ghost. Upon app restart, the Move Reconciler unconditionally destroys the source ghost (and its edits) in favor of the target location.
2. **Backup Restore Persistence Rollback**: `BackupService.restoreStructuredBackup` executes the OS notification flush (`cancelAllScheduledNotificationsAsync()`) inside the primary `try` block *after* the domain atomic write. If the OS notification call throws (e.g., transient native error), the `catch` block erroneously rolls back the entire successful domain state restore. This directly violates the core invariant that OS failures must never roll back domain persistence.

## Confirmed P2 Bugs
1. **Move Journal Sequential Failure Loss**: If an entity is moved A → B (fails) and then A → C (fails), the journal contains two operations. The reconciler processes A → B (copies to B, deletes A). It then processes A → C, but since A is deleted, it does nothing. The entity lands in B, ignoring the user's latest intent (C).
