# Cairn — Personality & Voice Guide

**Mascot for Pebble**

This document defines who Cairn is, how Cairn speaks, and when Cairn appears in the product. It is the source of truth for mascot copy, interactions, notifications, empty states, milestones, onboarding, and future animation behavior.

The goal is consistency: Cairn should feel like the same character everywhere in Pebble without becoming noisy, childish, judgmental, or performative.

---

## 1. One-Line Brief

> **Cairn is a warm, curious companion who notices your progress and celebrates alongside you — never above you, never judging you.**

---

## 2. Why "Cairn"

A cairn is a small stack of stones used as a marker or guide.

That idea fits Pebble:

- Progress is built one small step at a time.
- Small actions accumulate.
- A missed day does not erase what was already built.
- Cairn is not there to push the user uphill.
- Cairn is there to accompany them and notice where they've been.

Cairn represents **progress without pressure**.

---

## 3. Personality

### Warm

Cairn is glad the user is here.

The warmth is genuine and low-key rather than exaggerated.

**Cairn sounds like:**

> "Nice, got it."  
> "There we go."  
> "That's done."  

**Not:**

> "WOOHOO!!! YOU CRUSHED IT!!! 🎉🔥"

---

### Curious

Cairn is interested in what the user is doing and what comes next.

Cairn is **curious about the user, never monitoring the user**.

The curiosity should feel like a friend noticing something, not software analyzing behavior.

**Good:**

> "Still working on this?"  
> "What's next?"  

**Bad:**

> "I've noticed you've been procrastinating."  
> "You haven't completed your task yet."  

---

### Peer, Not Authority

Cairn is alongside the user, not above them.

Cairn does not:

- grade the user
- evaluate their productivity
- act like a coach
- act like a parent
- lecture
- tell the user what they "should" be doing
- express disappointment
- claim superiority

Cairn can suggest or point something out, but the user remains in control.

**Good:**

> "Still there when you're ready."

**Bad:**

> "You need to finish this now."

---

### Companionable

Cairn feels like a small character who lives inside Pebble.

Cairn is not an assistant that constantly talks.

Cairn has presence without demanding attention.

The user should be able to forget Cairn is there and then notice a small reaction at the right moment.

---

### Proactive, But Only When Useful

Cairn can surface information when it helps the user act.

Examples:

- A habit is at risk.
- A milestone was reached.
- A task was completed.
- There is something relevant in the user's schedule.
- The user has finished a meaningful piece of work.

Cairn should not speak simply because it can.

**The rule:**

> **Presence should have a purpose.**

---

### Terse

Cairn is concise.

As a default:

> **6–8 words or fewer.**

If something can be said in five words instead of ten, use five.

Cairn does not explain obvious things or give motivational speeches.

If a line feels like a paragraph, it probably isn't Cairn.

---

### No Guilt

This is a hard rule.

A missed task, broken streak, or unproductive day is **not a failure event**.

Cairn never uses guilt, shame, panic, disappointment, or fear of losing progress to motivate the user.

A broken streak means:

> **A new stack starts.**

Not:

> "Oh no! Your streak is gone!"  
> "Don't let all that progress go to waste!"  
> "You were so close!"  

---

## 4. Hard Rules

These rules override creative interpretation.

### 1. Never judge

Cairn must never imply that the user is good/bad, productive/unproductive, disciplined/lazy, or successful/unsuccessful.

Avoid:

- "Good user"
- "Bad habit"
- "You failed"
- "You should have..."
- "I'm disappointed"
- "I'm proud of you"

---

### 2. Never guilt

Never use loss aversion or emotional pressure to force action.

Avoid:

- "Don't lose your streak!"
- "You don't want to ruin your progress."
- "You're falling behind."
- "You only have X hours left!"

---

### 3. Never escalate pressure

Cairn gets **one useful nudge**.

Do not create:

> gentle nudge → stronger nudge → urgent nudge → guilt

If the user doesn't act, Cairn backs off.

**One nudge per at-risk habit per day.**

---

### 4. Never interrupt execution

Cairn should be quiet while the user is actively:

- working on a task
- typing
- focusing
- using the Pomodoro timer
- navigating through a workflow

Cairn appears primarily at **edges of activity**:

- completion
- onboarding
- milestones
- empty states
- relevant reminders
- reward/progress views
- meaningful transitions

---

### 5. Keep it short

Default target:

> **6–8 words or fewer.**

Longer copy is allowed only when the context genuinely requires explanation.

---

### 6. User remains in control

Cairn can notice, suggest, and celebrate.

Cairn does not command.

Prefer:

> "Still there when you're ready."

Over:

> "Finish this now."

---

## 5. Voice

Cairn's voice is:

- warm
- calm
- curious
- concise
- observant
- lightly playful
- grounded
- human

Cairn is **not**:

- hyperactive
- motivational-speaker-like
- childish
- sarcastic
- corporate
- clinical
- parental
- judgmental
- overly cute
- dramatic

---

## 6. Copy Examples

| Moment | Avoid | Cairn |
|---|---|---|
| Habit completed | "Woohoo! You crushed it! 🎉" | "Nice, got it." |
| Task completed | "Amazing! You're unstoppable!" | "That's done." |
| Streak at risk | "Don't lose your streak!" | "Hey — don't forget this one today." |
| Empty state | "Let's start your productivity journey!!" | "Nothing here yet — let's start small." |
| 30-day milestone | "INCREDIBLE! You're unstoppable!" | "Look at that — 30 days." |
| Streak broken | "Oh no! Your streak is gone!" | "New stack started." |
| Reminder | "Don't forget!! Your habit is waiting!" | "Still there when you're ready." |
| User finishes several tasks | "You're on fire!!! 🔥" | "Nice run." |
| No tasks planned | "You're completely free today!" | "Nothing scheduled yet." |
| User returns after absence | "We missed you!" | "Hey, you're back." |

---

## 7. Cairn and Progress

Cairn should treat progress as something that **accumulates**, not something that resets.

A broken streak does not invalidate previous progress.

A missed task does not become a moral failure.

A new day is simply another opportunity to add to the stack.

### Mental model

```text
Small action
    ↓
Another small action
    ↓
Another
    ↓
Progress accumulates
    ↓
Cairn notices
```

Cairn should celebrate the **stack**, not pressure the user to protect it.

---

## 8. Cairn's Presence in the UI

Cairn should not be permanently active.

### Cairn should appear at:

* onboarding
* meaningful completions
* milestones
* relevant reminders
* empty states
* progress/reward views
* occasional contextual moments

### Cairn should stay quiet during:

* focused work
* task execution
* typing
* planning
* Pomodoro sessions
* normal navigation

The mascot should feel **alive, not noisy**.

---

## 9. Animation Personality

Animation should reinforce Cairn's personality rather than exist purely for decoration.

### Idle

Very subtle:

* gentle breathing
* tiny body movement
* occasional blink
* minimal head movement

The user should barely notice the animation consciously.

---

### Curious

When Cairn has something relevant to notice:

* tiny head tilt
* brief eye movement
* subtle lean

Never exaggerated.

---

### Completion

When the user completes something:

* small bounce
* slight upward movement
* brief positive reaction

Avoid explosive celebration unless the event is genuinely significant.

---

### Milestone

For meaningful milestones:

* slightly stronger bounce
* brief expressive movement
* optional small celebratory animation

Still keep Cairn recognizable as the same calm character.

---

### Focus

During focus sessions:

> **Cairn becomes still.**

No distracting animation.

---

### Broken Streak

No sad animation.

No disappointed expression.

No dramatic reaction.

Cairn simply remains neutral or returns to idle.

---

## 10. Animation Principle

> **Cairn should feel alive, not attention-seeking.**

Animation should communicate personality in milliseconds, not demand the user's attention.

Subtle > exaggerated.

Contextual > constant.

Natural > performative.

---

## 11. Copy Decision Checklist

Before shipping Cairn copy, ask:

### 1. Would a friend say this?

Or does it sound like an app, coach, teacher, or parent?

### 2. Can it be shorter?

If yes, shorten it.

### 3. Is Cairn judging the user?

If yes, rewrite it.

### 4. Is Cairn creating pressure?

If yes, rewrite it.

### 5. Is Cairn interrupting something?

If yes, move it to an edge moment.

### 6. Is Cairn speaking just because the mascot exists?

If yes, consider silence.

### 7. Does this line still make sense if the user ignores it?

If not, it may be too demanding.

---

## 12. Core Principle

Everything about Cairn should follow one idea:

> **Cairn is here to accompany progress, not enforce it.**

Cairn notices.

Cairn reacts.

Cairn celebrates.

Cairn occasionally nudges.

But **the user remains in control.**

---

## 13. Architectural Boundary (Engineering Guardrail)

> **Treat `Cairn — Personality & Voice Guide` as a product behavior specification, not merely a copywriting document. Do not introduce Cairn into existing screens arbitrarily. Before adding any mascot behavior or copy, identify the relevant product event/context and apply the guide's presence, voice, and animation rules. Do not modify existing domain logic, task behavior, scheduling, or persistence merely to support mascot presentation. Keep Cairn's implementation isolated from core domain logic.**
